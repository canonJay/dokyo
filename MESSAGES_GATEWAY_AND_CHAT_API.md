# Документация по WebSocket Gateway и REST API для чатов и сообщений

## 1. Общая архитектура

- **messages.gateway.ts** — WebSocket gateway для обмена сообщениями в реальном времени.
- **messages.service.ts** — сервис для работы с сообщениями и чатами через Prisma.
- **chats.controller.ts** — REST API для управления чатами (создание, получение, удаление и т.д.).

---

## 2. WebSocket Gateway: messages.gateway.ts

### Подключение
- Клиент подключается к серверу по WebSocket (обычно через `/socket.io`).
- Для аутентификации используется JWT-токен (guard WsAuthGuard).

### События (методы)

#### 2.1. `send_message`
- **Назначение:** Отправить сообщение в чат.
- **Payload:**
  ```json
  {
    "chatId": "string", // ID чата
    "text": "Текст сообщения"
  }
  ```
- **Ответ:**
  ```json
  {
    "success": true,
    "message": { ...messageObject }
  }
  // или
  {
    "success": false,
    "error": "Ошибка"
  }
  ```
- **Бизнес-логика:**
  - Проверяется доступ пользователя к чату.
  - Сообщение сохраняется в БД.
  - Всем участникам чата отправляется событие `new_message` с этим сообщением.

#### 2.2. `join_chat`
- **Назначение:** Вступить в чат (подписаться на room).
- **Payload:**
  ```json
  { "chatId": "string" }
  ```
- **Ответ:**
  ```json
  {
    "success": true,
    "messages": [ ... ] // История сообщений
  }
  ```
- **Бизнес-логика:**
  - Проверяется доступ пользователя к чату.
  - Клиент подписывается на room чата.
  - Возвращается история сообщений.

#### 2.3. `leave_chat`
- **Назначение:** Покинуть чат (отписаться от room).
- **Payload:**
  ```json
  { "chatId": "string" }
  ```
- **Ответ:** `{ "success": true }` или ошибка.
- **Бизнес-логика:**
  - Проверяется доступ пользователя к чату.
  - Клиент отписывается от room чата.

#### 2.4. `get_chat_messages`
- **Назначение:** Получить историю сообщений чата.
- **Payload:**
  ```json
  { "chatId": "string" }
  ```
- **Ответ:**
  ```json
  {
    "success": true,
    "messages": [ ... ]
  }
  ```
- **Бизнес-логика:**
  - Проверяется доступ пользователя к чату.
  - Возвращается история сообщений.

#### 2.5. `get_my_chats`
- **Назначение:** Получить список чатов пользователя.
- **Payload:** отсутствует.
- **Ответ:**
  ```json
  {
    "success": true,
    "chats": [ ... ]
  }
  ```
- **Бизнес-логика:**
  - Возвращаются все чаты, где пользователь — участник.

## 3. REST API для чатов: chats.controller.ts

### 3.1. Создать чат между пользователями
- **POST /chats**
- **Body:**
  ```json
  { "users": ["userId1", "userId2"] }
  ```
- **Ответ:** объект чата с участниками и сообщениями.
- **Бизнес-логика:**
  - Если чат между этими пользователями уже есть — можно возвращать его (или создавать новый).
  - Оба пользователя видят этот чат в списке своих чатов.

### 3.2. Создать чат с поддержкой
- **POST /chats/createSupportChat**
- **Body:** отсутствует (или id пользователя берётся из токена).
- **Ответ:** объект чата с support-юзером.

### 3.3. Получить свои чаты
- **GET /chats**
- **Ответ:** массив чатов пользователя.

### 3.4. Получить чат между двумя пользователями
- **GET /chats/getMyChatByUserId/:userId**
- **Ответ:** объект чата (если есть).

### 3.5. Получить чат по id
- **GET /chats/:id**
- **Ответ:** объект чата.

### 3.6. Удалить чат
- **DELETE /chats/:id**
- **Ответ:** true/false.

## 4. Как реализовать:

### 4.1. Диалог между двумя пользователями
- На фронте пользователь выбирает другого пользователя и отправляет ему сообщение.
- Фронт вызывает POST /chats с массивом из двух id (свой и собеседника).
- Если чат уже есть — возвращается существующий, иначе создаётся новый.
- После этого оба пользователя могут отправлять сообщения через WebSocket (`send_message`), получать новые сообщения в реальном времени, видеть историю и т.д.

### 4.2. Групповые чаты
- Для группового чата в массив users передаётся больше двух id.
- В сервисе/модели чат должен поддерживать массив участников (users: User[]).
- Для добавления участника — реализовать PATCH /chats/:id/addUser (или аналогичный endpoint), который добавляет пользователя в массив users чата.
- Для удаления — PATCH /chats/:id/removeUser.
- Все участники получают новые сообщения через WebSocket.

## 6. Важные моменты для фронта
- Для всех WebSocket событий требуется JWT.
- Для групповых чатов используйте массив users в чате.
- Для получения истории сообщений используйте событие `get_chat_messages` или GET /chats/:id.
- Для создания чата с пользователем — POST /chats с двумя id.
- Для создания группового чата — POST /chats с массивом из 3+ id.
- Для добавления/удаления участников — реализовать отдельные endpoints.

---

## 8. Схема данных (упрощённо)
- **Chat:** { id, users: User[], messages: Message[] }
- **Message:** { id, chatId, userId, text, fileUrl?, createdAt }

## 9. FAQ
- **Q:** Как узнать, есть ли уже чат между двумя пользователями?
  **A:** Используйте GET /chats/getMyChatByUserId/:userId или фильтруйте чаты по users на фронте.
- **Q:** Как добавить пользователя в групповой чат?
  **A:** PATCH /chats/:id/addUser с body { userId }.
- **Q:** Как отправить файл?
  **A:** Сначала загрузить файл через REST, затем отправить ссылку через WebSocket.
